# OA 最近三天补卡提醒

浏览器内运行的 Tampermonkey 脚本。在普通 HTTP/HTTPS 网页显示入口，点击后新开 OA 检查前三个完整自然日；默认每天北京时间 09:00 自动检查。浏览器关闭时不运行，也不会唤醒浏览器。

## 安装与自动更新

[安装最新版脚本](https://raw.githubusercontent.com/yzbf-lin/oa-attendance-reminder/main/oa-attendance-reminder.user.js)

1. 在安装了 Tampermonkey 的浏览器中打开上面的原文件链接，确认安装。若浏览器显示源码，可将原文件全文粘贴到油猴编辑器保存。
2. 首次安装或从旧的定制版迁移时，停用旧副本，使用油猴菜单「配置 OA（仅保存在本机）」填入自己的站点配置。公开版不内置任何公司的地址。
3. 保存配置后刷新已打开的网页。右下角「OA 考勤检查」和油猴菜单都可以立即触发，新标签中的正常、异常及失败结果均有反馈。
4. 在油猴设置中开启脚本更新检查。脚本使用公开的 `@updateURL` / `@downloadURL`；发布更高版本后由油猴检查更新，更新后刷新网页生效。站点和时间设置保存在 GM 本地存储中，不会被脚本更新覆盖。

未配置时只显示「配置 OA 考勤」，不会自动打开网站或读取页面对象。普通网站仍需允许油猴运行；浏览器内部页、扩展页和其他没有油猴的浏览器不运行此脚本。

## 本机配置

通过菜单粘贴 JSON。下面只是虚构的适配示例，不能直接用于真实 OA：

```json
{
  "recordUrl": "https://oa.example/oa.html/attendance/record",
  "oaOrigins": ["https://oa.example"],
  "oaPath": "/oa.html",
  "applyPath": "/oa.html/apply/list",
  "loginOrigins": ["https://sso.example"],
  "vueRoot": "OA_APP",
  "componentName": "attendanceRecord",
  "loginButtonSelector": "#login-submit",
  "hour": 9,
  "minute": 0
}
```

- `recordUrl`：打卡记录页面的完整地址，不含登录凭据、查询参数或片段。
- `oaOrigins`：允许访问的 OA 来源，精确匹配协议、域名、端口；记录页来源自动包含在内。
- `oaPath` / `applyPath`：OA 的基础路径和补卡申请路径；申请页须与记录页同源且位于 OA 路径内。
- `loginOrigins`：允许辅助登录的来源；空数组关闭辅助登录。仅处理 `/login` 路由且 `service` 指向所配置 OA 的登录页。
- `vueRoot` / `componentName`：已适配页面的 Vue 根对象名及记录组件名。
- `loginButtonSelector`：现有登录按钮的 CSS 选择器；脚本只点击按钮，不读取或填写登录字段。
- `hour` / `minute`：北京时间的自动检查时间。

此脚本的查询适配仍要求页面提供 `permission` / `getAttendance` 方法、`initQuery` / `query` 查询对象，以及日期、排班、状态、当前用户标识等结果字段。它不是适用于所有 OA 产品的通用采集器；更改地址并不会自动适配不同系统。

**真实配置只保存在自己的浏览器中。不要把公司配置、截图或真实记录提交到此公开仓库、Issue 或 Pull Request。**

## 检查与登录规则

- 检查昨天、前天、大前天，不包含今天；仅排班为「工」且状态不为「正常」时提醒核对、补卡。
- 查询必须完整覆盖三天且全部属于当前登录用户。缺日期、分页不完整、权限不明、超时或结构变化均提示检查未完成，不报告正常。
- 每天定时检查成功后不再自动重复；手动触发不受当天完成标记限制。设定时间前手动检查不占用当天定时检查。
- 多标签通过 GM 存储中的短期锁协调；手动检查在新标签排队，不会跳走其他 OA 表单。
- 网页后台节流可能推迟检查；晚于设定时间恢复网页时补做当天检查。
- 登录过期时，在明确配置的登录来源上每天最多尝试点击一次原有登录按钮。凭据缺失、验证码、扫码或登录失败需要用户处理。
- 补卡入口只打开原有申请页，不填写或提交申请。

## 数据与公开范围

公开内容只有通用脚本、更新元数据、文档及使用虚构记录的测试，不含实际站点地址、组织适配标识、账号、密码、Cookie、Token、员工信息或考勤明细。仓库从新历史开始，使用 GitHub noreply 提交身份。

脚本没有后端、遥测或外部消息推送。考勤查询和登录复用已配置 OA 的原生页面逻辑；普通网页仅显示入口和运行定时器，不读取正文或表单。考勤结果只在 OA 页的内存及弹窗中显示，不写入 GM 存储。GM 存储仅保存本地配置、少量调度标记及临时标签状态。更新检查只获取本仓库的脚本文件，不上传上述配置或考勤数据。

## 验证与发布

```sh
node --check oa-attendance-reminder.user.js
node --test tests/reminder.test.cjs
```

测试使用虚构域名与数据，覆盖跨域开页、手动与定时检查、并发、登录恢复、失败退避、配置校验、未配置行为及本地配置保留。模拟测试不等同于在任意真实 OA 上完成验证。

发布时同时递增 `.user.js` 中的 `@version` 和 `SCRIPT_VERSION`，将其元数据头同步到 `.meta.js`，运行检查后推送 `main`。不得发布自己的本地配置文件；新增文件也须在提交前审查。
